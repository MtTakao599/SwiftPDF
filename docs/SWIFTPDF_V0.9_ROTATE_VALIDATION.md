## 3. レンダリング比較方法

`pdfcraft_render::PageRenderer` で scale 2 の RGBA を描いた。回転前は 1190×1684（2,003,960 画素）。90° と 270° は 1684×1190。180° と 360° は 1190×1684。

比較は、回転前の画像を時計回りに同じ角度だけ回したものと、`/Rotate` を付けた PDF を描き直した画像である。ページの縦横が入れ替わる角度では、描き直し側の幅と高さがビットマップ側と一致することを先に見た。

実行前に決めた許容は次のとおりである。

- 色領域の重心: 6 px 以内。scale 2 で 3 pt であり、28 pt のマーカーより小さい。ベクトルの輪郭を描き直したときと、すでにアンチエイリアスされた画像を回したときとで、しきい値を超えた画素の重心が数 px ずれても、向きの誤り（別の角へ移る）は数百 px になる。
- 各色の画素数: 回転前の 0.65 倍から 1.40 倍。輪郭の描き直しで被覆が変わる分である。消えた領域は 0 になり、この範囲に入らない。
- チャネル差が 40 を超える画素の割合: 5% 以内。縁のアンチエイリアスはこの中に収まり、領域ごと動く誤りは超える。

測定値はこの許容より小さかった。許容は測定後に広げていない。

| 角度 | チャネル差 40 超の画素 | 割合 | 再オープンとの差 |
|---|---:|---:|---:|
| 右 90° | 18 | 0.000009 | 0 |
| 左 90° | 18 | 0.000009 | 0 |
| 180° | 34 | 0.000017 | 0 |
| 360°（+90° を 4 回） | 0 | 0 | 0 |

差が出た画素はシアンの輪の縁である。輪の画素数は回転前 7,510 に対し、右 90° と左 90° が 7,492、180° が 7,493 だった。ほかの領域は画素数が一致した。重心の最大ずれはシアンの輪で約 0.12 px である。四隅、紫、オレンジ、文字、マゼンタ、理事長印の青緑と赤は、測定上 0.02 px 未満だった。

回転前、右 90°、左 90°、180°、360° の PNG を開いて見た。数値と比較が一致している。

## 5. 一般・日付・理事長印の結果

合成ページでは、3 つの印影は回転前にページ下部へ置いた。回転後もページ 0 の注釈のままである。開き直してもスタンプ注釈は 3 つともページ 0 である。

- 一般スタンプ（マゼンタの正方形）は、ページと一緒に移動する。形は保たれる。
- 日付印（シアンの輪）もページと一緒に移動する。輪は残る。縁の数画素だけが描き直しで変わる。
- 理事長印は、回転前は左が青緑、右が赤である。右 90° では上が青緑、下が赤になる。左 90° では上が赤、下が青緑になる。180° では左右が入れ替わる。印影の画像がページの `/Rotate` と一緒に回っている。

日付印の UI 経路（`start_date_stamp` から `commit_stamp_place`）では、回転後もスタンプはページ 0 の 1 件のままである。描画にインクが残り、保存して開き直した PDF にもインクが残る。Undo で角度を戻してもインクは残る。理事長印の承認履歴は空のままである。日付印は承認を作らない。

理事長印の UI 経路は、一時ディレクトリの `seals.bin` だけを使う。2 ページの白紙に合成 PNG を 1 ページ目へ置き、そのページだけを 90° 回した。`SealUse.page` は 1（1 始まり）のままである。色は 1 ページ目に残り、2 ページ目には色が付かない。承認履歴の件数は増えない。Undo の後も同じである。ページ番号の記録と、描いたページは一致している。

## 6. 回転前後の配置比較

印影を先に置いてから回すと、印影は本文と同じ重心移動をする。上の表がこの順序である。

回してから別の緑の正方形を置くと、その印影はページ 0 に付く。2 ページ目の非白画素は 0 のままである。その印影の Undo は回転を戻さない。先に置いた 3 つの印影と「管理センター」は残る。回転を Undo すると角度は 0 に戻り、先に置いた 3 つの印影はページ 0 に残る。

回転の後に置いた印影は、置いた時点の `/Rotate` に合わせて見た目を正す（`orient_image_stamp`）。その後に回転を Undo すると、ページの角度だけが戻り、印影オブジェクトはページ 0 に残る。見た目の補正は印影側に残る。これは配置処理の既存の動きである。印影が消えること、別ページへ移ることはなかった。

## 7. 署名検出の監査

`Document::is_signed` は `signatures` のいずれかが `signed` のときだけ真である。一覧は `pdfcraft_sign::pdf::list_cached` が作る。

検出するもの:

- `/AcroForm` の `/Fields` にある、`/FT /Sig` かつ `/T` があるフィールド。`/V` が辞書に解決できるとき `signed` は真である。暗号の検証に成功することは条件ではない。ダミーの `/ByteRange` と `/Contents` でも拒否する。
- フィールドの外にある文書タイムスタンプ。`/SubFilter /ETSI.RFC3161`、`/Type` が `/DocTimeStamp` または `/Sig`、かつ `/ByteRange` があるオブジェクトである。これも `signed` が真になり、回転は拒否される。

検出しないもの。フィールド一覧が空でも、未署名とは断定できない。

- `/T` が無い `/FT /Sig`。`sig_fields` は名前があるフィールドだけを集める。`/V` が署名辞書でも一覧に出ない。
- `/V` が辞書でも null でもない値。フィールドは出るが `signed` は偽である。`Field::has_foreign_value` はこの形を識別するが、`is_signed` は見ていない。
- カタログの `/Perms` / `/DocMDP` が指す署名辞書。AcroForm のフィールドでなければ一覧に出ない。
- どこからも参照されない `/Type /Sig` と `/ByteRange`。`/SubFilter` が `/ETSI.RFC3161` でなければ文書タイムスタンプにもならない。
- `/ByteRange` 自体は探索キーではない。辞書を見つけた後の検証で読む。
- `is_signature_dict`（`/Type` が `/Sig`、`/DocTimeStamp`、`/SigRef`、`/TransformParams`、または `/FT /Sig`）は、すでに署名がある版の変更分類に使う。未署名かどうかの判定には使っていない。

増分更新は、開いたファイルの最新の相互参照を見る。後の版で AcroForm に署名辞書を足したファイルは、増分の先頭に前の版が残っていても署名ありになる。`/Perms` だけ、または未参照の `/ByteRange` だけを足した増分は、署名ありにならない。

## 8. 署名保護テスト

合成した構造と、暗号学的に有効な署名は分けて記録した。既存の PKCS#12 試験（`signed_and_restricted_documents_refuse_page_rotation_before_it_changes_them`）は再実行して通過した。値のある署名は、閲覧専用がオフのセッションでも回転前に拒否される。

今回の合成 PDF の結果は `signatures.txt` のとおりである。

| 構造 | `is_signed` | 回転 |
|---|---|---|
| `/FT /Sig`、`/T` あり、`/V` が署名辞書 | 真 | 拒否。ページは不変 |
| `/V` なし | 偽（フィールドは出る） | 適用される。未署名フィールド |
| `/V` が null | 偽 | 適用される。未署名フィールド |
| `/V` が文字列 | 偽 | 適用される。検出の穴 |
| `/T` がなく `/V` が署名辞書 | 偽。一覧は空 | 適用される。検出の穴 |
| `/Perms` / `/DocMDP` だけ | 偽。一覧は空 | 適用される。検出の穴 |
| 未参照の `/Type /Sig` と `/ByteRange` | 偽。一覧は空 | 適用される。検出の穴 |
| `/Type /DocTimeStamp`、`/SubFilter /ETSI.RFC3161`、`/ByteRange` | 真 | 拒否。ページは不変 |

空のフィールドと null の `/V` は、検出側のコメントどおり未署名フィールドである。回転できることは、その定義に沿っている。

残りの 4 つは、署名に見える構造を回転できてしまう。試験は現状を記録し、その許可を正しい仕様としては固定していない。製品コードは変えていない。

最小の修正案は、`Edit::RotatePages` の前に次も拒否することである。

- 署名フィールドの `/V` が null でも辞書でもない（既存の `has_foreign_value`）。
- `/T` が無くても、`/FT /Sig` の `/V` が辞書である。
- カタログの `/Perms` に `/DocMDP` または `/UR3` がある。
- `/Type /Sig` または `/DocTimeStamp` と `/ByteRange` を持つオブジェクトがある。AcroForm に載っていないものも含む。

この修正は入れていない。

## 9. 保存と再オープンの結果

回転の保存は増分更新である。保存バイト列は、回転前の作業バイト列で始まる。前の版はファイルの先頭に残る。これはページ削除のバイト消去を保証するものではない。ページ削除は今回も拒否されたままである。

- ページ辞書の `/Rotate` は直接の整数になる。右 90° は 90、左 90° は 270、180° は 180、4 回の +90° は 0。
- ページの `ObjRef` は変わらない。`/Pages` の `/Count` は 2、`/Kids` は 2 のままである。2 ページ目の角度は 0 のままである。
- 間接参照の `/Rotate` と、ページツリーから継承した `/Rotate` は、既存の organize 試験が通過した。共有の角度オブジェクトは書き換えず、ページ辞書へ直接の整数を書く。
- 同じ呼び出しの重複インデックスは 1 回だけ回る。`[0, 0]` の +90° は 90 であり、180 にはならない。
- 範囲外の 9 を `[0, 9]` に含めると `NoSuchPage(9)` で、どちらのページも変わらない。
- 保存した PDF は開き直せる。角度、追加テキスト、スタンプ数、描画が回転直後と一致する。

## 10. Undo／Redo

Undo は直近の 1 手だけを戻す。

- 印影を置いてから回し、Undo すると角度が戻り、印影は残る。Redo で角度が戻る。印影はページ 0 のままである。
- その次の Undo は、最後に置いた印影を外す。角度は 0 のまま、ほかの印影と「東京」は残る。回転より前の印影を、回転を残したまま外す操作は、このスタックには無い。
- 回してから印影を置き、その印影を Undo すると、角度は 90 のまま、先の印影は残る。その次の Undo で角度が 0 に戻り、先の印影と「管理センター」は残る。
- 削除と移動は `EditError::ViewOnly` のままである。失敗した適用は作業バイト列を取り替えない。

回転以外の編集が Undo で壊れることは、この手順では起きなかった。

## 11. 原本保護

- 合成の原本ファイルのバイト列は、テキスト追加、印影、回転、別名保存の後も一致した。
- `save_bytes`（上書き保存）は `EditError::ViewOnly` を返す。失敗した後も回転は 90 のまま残り、その後の別名保存は成功する。
- 閲覧専用のコマンド一覧に `file.save` は無い。`page.rotate`、`page.rotate_ccw`、`page.delete`、`page.extract`、`page.insert` も、`PageRotate` を試験が付与してもコマンドとしては拒否される。
- 原本と同じパスは `SameAsOriginal`、既存ファイルは `DestinationExists` で拒否される。既存ファイルの中身は `KEEP` のままである。新しいパスへ書いた PDF は、開き直すと `/Rotate` が 90 である。
- Ctrl+S に相当する `file.save` は有効にならない。Ctrl+Shift+S の別名保存経路は、今回の検証ではコマンドを開いていない。既存の別名保存試験の経路は通過した。

## 14. GUI有効化の可否

有効にしない。

表示、再オープン、Undo、原本保護は、合成 PDF では崩れていない。署名検出には穴がある。`/Perms` の `/DocMDP`、名前の無い署名フィールド、辞書でない `/V`、未参照の `/ByteRange` は、署名に見えるのに回転できる。フィールド一覧が空であることを未署名の証明にはできない。

この穴を塞ぐまで、`page.rotate` と `page.rotate_ccw` は閉じたままにする。`Capability::PageRotate` は起動時に付与しない。`set_view_only(false)` は呼ばない。削除、並べ替え、抽出も開かない。
