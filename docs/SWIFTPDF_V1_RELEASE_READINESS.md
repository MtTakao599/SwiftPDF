## 2. 現在の実装済み機能

SwiftPDF は、起動時から閲覧専用で動く（`apps/pdfcraft/src/main.rs` 360〜367 行）。

`set_view_only(true)` のあと、次の 5 つの許可だけを与える。
- `grant_save_as`
- `grant_edit_text`
- `grant_print`
- `grant_stamp`
- `grant_page_rotate`

閲覧専用はどこでも解除しない。本家 PdfCraft にコードがあっても、この許可の外にある機能は数えない。

使えるコマンドは次のとおり。
- `command_policy.rs` の閲覧用一覧（開く、閉じる、検索、表示、設定、ヘルプなど）
- `file.save_as`、`edit.text`、`edit.undo`、`edit.redo`、`comment.stamp`、`page.rotate`、`page.rotate_ccw`、`print.dialog`

ホーム画面の「結合、分割、編集、変換、圧縮」は「準備中」の表示だけで、何も実行しない。

## 5. セキュリティとデータ保護の評価

### 5.1 理事長印ファイルを 2 つのプロセスが書くと、一方の追加分が消える可能性（P0、要再現確認）

`seal_store.rs` の `SealStore` は、起動時に 1 回だけ `seals.bin` を読む。
- 追加、削除、倍率、効果、使用履歴の追加のたびに、メモリ上の全体を暗号化して原子的に書き戻す（`write`、362〜381 行）。
- 書く前に、ファイルを読み直さない。
- ロックもしない。

単一インスタンスの引き渡しは、ファイルだけを指定した起動に限られる（`main.rs` 217 行）。スタートメニューから 2 回起動する、ファイル無しで起動する、オプション付きで起動する、のどれでも、別のプロセスが立ち上がる。

2 つのプロセスがどちらも理事長印を使うと、後から書いた方が、先に書いた方の登録や使用履歴を上書きする（コード上、そうなる）。
- ファイルは壊れない（原子的な置き換え）。
- しかし、承認・使用の記録が欠ける。品質基準の必須 5「承認・監査履歴を破損しない」に反する。
- STEP 116 で、製品の `seal_store.rs` を変えずに別プロセスから動かし、合成データで再現した。登録の消失、履歴の消失、削除した印影の復活が、すべて決定的に起きた。同時書き込みでは 20 回中 20 回消えた。書く前に読み直すだけでは防げなかった。ファイルの破損と、利用者への通知は無かった。設計案は `SWIFTPDF_V1_SEAL_CONCURRENCY_DESIGN.md`。

### 5.2 使用履歴は 400 行で古い順に消える（P0、要判断）

`append_event` は、400 行を超えた分を古い方から捨てる（325〜328 行）。設計どおりだが、監査記録が、通知なしに失われる。

選べる対処:
- 上限を残し、書き出しやバックアップを用意する。
- 上限に近づいたら警告する。
- 上限を上げる。

### 5.3 その他（確認済みの保護）

- 原本と既存の保存先は上書きしない（`save_path::write_new_file`。STEP 113 でも確認）。Ctrl+S は拒否する。
- 署名や権限で保護された PDF は回転を拒否する。xref が不明確な PDF も拒否する（STEP 112）。
- 理事長印は DPAPI（現在のユーザー）で暗号化する。復号できないファイルは、そのまま残して上書きしない。書き込みに失敗したら、メモリ上の状態も元に戻す。
- パッケージ（`package.ps1`）は、`pdfcraft.exe` と `pdfcraft-cli.exe` を入れない。Noto CJK を埋め込んだら失敗する。
- `--control`（UI 操作チャネル）は SwiftPDF では拒否する。MCP は、CLI を配布しなければ届かない。

要判断条件への意見（決めるのは利用者）:
- **既知の 2 件のテスト失敗**: 製品の不具合ではない根拠がある。ただし「新規失敗 0」を毎回人が見分ける状態は危うい。公開前に原因を確定し、直すか、環境依存として承認のうえ扱いを決める（P1）。
- **WARP 並列クラッシュ**: テストハーネスの問題で、製品経路は見つかっていない。v1.0.0 では直さず、単一スレッドで実行する手順を正式にする（P2）。
- **修復 PDF の再保存と署名保護**: 原本は守られ、コピーのガードも働く。それでも、修復済みのコピーを作れることを利用者に知らせる必要がある（既存の帯が予告している）。仕様として残すか、修復ファイルの別名保存時に確認を出すかは要判断。
- **未確定編集を UI から届くようにするか**: 仮置きのスタンプは、少なくとも終了確認の対象にする方がよい（P1）。
- **署名判定の限界の説明**: 「署名の有効性は確認しない。署名の可能性があれば回転しない」と、平易に伝える（11 節）。
- **配布ファイルの署名**: 署名しないと、SmartScreen の警告が出る。証明書の入手は利用者の判断（`sign.ps1` は用意済み）。

既知の安全上のリスク（5.1、5.2、ジャンクション、仮置き）は、文書に書いただけでは解決済みとしない。

## 10. 理事長印データの保護と移行

| 状況 | 挙動（コードから） | 備考 |
|---|---|---|
| 保存場所 | 通常は `%LOCALAPPDATA%\SwiftPDF\seals.bin`、ポータブルでは `<exe>\Data\seals.bin` | `app.ron` には入れない |
| Windows ユーザーとの結び付き | DPAPI の現在ユーザー。同じユーザーなら、パスワードを変えても復号できる | 別ユーザーは復号できない |

| アンインストール | 削除しない | 説明が必要 |
| 更新インストール | 保持される（ユーザーフォルダ） | 実機では要確認 |
| バックアップと復元 | 機能が無い。同じユーザー・同じ PC でファイルを写すことはできる | 別 PC での復元は不可 |
| アクセス権限 | 独自の ACL は設定しない。`%LOCALAPPDATA%` の既定の権限に依存する | ポータブルでは、フォルダの権限次第 |
| 暗号化できない場合 | 登録・変更を拒否する。ファイルを変えない。メモリ上も元に戻す | Windows 以外では使えない |
| 複数プロセス | **保護が無い（5.1）** | P0 |
| 履歴の上限 | 400 行。古い行から消える（5.2） | P0（要判断） |

利用者向けの案内文の案（誤解を避ける）:

> 理事長印は、この Windows ユーザーだけが使えるように暗号化して保存します。別のパソコン、別のユーザー、Windows の再インストール後には使えません。その場合は、元の画像から登録し直してください。アンインストールしても理事長印のデータは削除されません。

検証は、合成の印影画像と、検証専用のポータブルフォルダだけで行う。利用中の `seals.bin` は使わない。
