## 3. 失敗した 2 試験の詳細

同一の全体並列実行（117E `logs\parallel\fail-18.txt`、run 18）で両方落ちた。

### 対象 A

タブを切り替えたあとに、準備中の押印をキャンセルする試験。登録は成功している。その後の prepare / cancel の書き込みで失敗。

表示：`使用履歴を記録できないため、押印しませんでした。理事長印のファイルを書き出せませんでした。`

これは `VaultError::Io(WRITE_ERROR)`。DPAPI 失敗（「印影を暗号化できませんでした」）でも、ロック待ち（Busy）でも、試験フック（`test: stopped`）でもない。

### 対象 B

加工した理事長印を複数回確定する長い試験。後半の確定で失敗。

表示：`使用履歴を記録できないため、押印しませんでした。保存した理事長印のファイルを読み直して確認できませんでした。`

試験は `use_committed` を期待し、実際は `use_cancelled`。製品は押印を確定せず、記録できない旨で止めている。

同時に走っていたのは、同じプロセスの `seal_flow` / `seal_store` / `seal_store_v2` / `stamps_ui` と、staging・ジャンクションを使う他の UI 試験。

## 4. 保存・Verify の内部処理

`SealVault::store` はフォルダーロックの下で次を行う。

1. JSON を作り、現行ユーザーの DPAPI で暗号化し、`SWSEAL2\n` を付ける（`encode`）。
2. 既存ファイルなら staging へ書いて `sync_all` し、対象へ rename（`write_atomically`）。初回は hard link / `create_new`。
3. 共有違反（Win32 32/33）と `PermissionDenied` だけ、約 2 秒再試行する。
4. 書いたバイトを読み、長さと内容を比較する。続いて復号して `Snapshot` が一致するか見る。

`WRITE_ERROR` になる箇所：

- `write_atomically` が再試行のあと失敗
- `create_new_file` / `create_new_plain` の失敗
- JSON の serialize 失敗（DPAPI 失敗は別文言）

`Verify` になる箇所：

- 書いた直後にファイルがない（`verify_missing`）
- 読めたがバイト列が違う（`verify_bytes`）
- バイトは同じだが復号結果が `Snapshot` と違う（`verify_decode`）
- バイトは同じだが復号できない（`verify_undecodable`）

117E のログには、このどれか・Windows のエラー番号は残っていない。製品は当時、すべての I/O を固定文言に畳んでいた。

## 11. ストア・監査への影響

コードと既存試験、および利用者の 4 項目から：

- 登録・更新・削除の競合は `Conflict` で拒否し、呼び出し側の要求は載せない。
- 同時更新はロックの下で最新を読み、古い generation は拒否する。履歴は消さない。
- `use_prepared` → `use_committed` / `use_cancelled`、Undo/Redo の `use_redone` 等は状態機械で検査する。
- 監査の書き込みに失敗すると押印しない。今回の失敗もその経路である。
- 要復旧は `hold_output` のあと、保存・名前を付けて保存・印刷・書き出し・編集・Undo を拒否する。
- 旧版の遅延書き戻しは取り込みず、退避して記録する。
- 原本 PDF は別名保存のみ。

実データの消失、監査なしの押印成功、要復旧を抜けた出力は、今回再現していない。
