## 2. SwiftPDF の全機能一覧

製品は起動時に閲覧専用のまま、次の 4 つだけを追加で許可する（`apps/pdfcraft/src/main.rs` の `app_creator`）。

- `set_view_only(true)` のあと `grant_save_as()`
- `grant_edit_text()`
- `grant_print()`
- `grant_stamp()`

上書き保存（`file.save`）と書き出しは許可しない。閲覧専用の基本許可は `crates/ui-egui/src/command_policy.rs` の `VIEW_ONLY`。ページ操作、既存テキストの編集、画像、注釈、フォーム、墨消し、署名作成、最適化、OCR はその一覧に無く、`command_allowed` の例外にも無い。エンジンと UI の実装はツリーに残っているが、製品としては拒否される。状態は「無効化」。

既定の画面は簡単モード（`set_ui_mode(UiMode::Simple)`）。簡単モードは閲覧バー、テキスト入力、スタンプバー、右レールを描く（`crates/ui-egui/src/lib.rs` の `simple` 分岐）。詳細モードに切り替えても、閲覧専用の拒否は残る。

- スタンプ: 本家の `comment.stamp` は注釈スタンプである。SwiftPDF はそれに加え、登録画像、データー印、理事長印をこのセッションのスタンプ権限で置ける。理事長印だけ承認と履歴と加工を持つ。

- 保存: 本家の正規操作は上書き保存である。最新版は修復が必要なファイルを全書き出しし、別名保存では古い増分を落とす。SwiftPDF はその上書きを製品から外している。
- 保護: 本家はパスワード設定と解除を持つ。SwiftPDF は権限の表示だけを許可する。

## 10. v0.8.0 以降の開発候補

既に製品として使える機能（閲覧、テキスト追加、追加テキストの再編集、別名保存、原本拒否、印刷、グレースケール、一般スタンプ、データー印、理事長印）は、新規候補にしない。

評価の軸は、利用頻度、実務での usefulness、今の権限モデルとの整合、難易度、試験の量、壊すリスク、本家の差分をどこまで使えるか。

| 優先度 | 候補 | 判断 |
|---|---|---|
| 高 | 本家から、SwiftPDF が実際に通す経路の修正だけを選ぶ | テキストのエンコード、別名保存のコピーの中身、印刷のレイヤー、ズーム、ダイアログ中のショートカット、出力パス。一括マージはしない。印影と原本拒否に触る差分は落とす |
| 高 | 保存の確認の抜けを閉じる | 「既にあるファイル」と「原本」の拒否が、印刷以外のすべての書き込みで揃っているかを試験で固定する。新機能ではない |
| 中 | ページ操作を、別名保存の範囲だけで許可する | 回転、削除、並べ替え、抽出。コードは既にある。結合、分割、ページサイズ、本家最新の整理 UI は含めない。承認済みの印はページが変わったら無効のまま |
| 中 | UI | 詳細モードで見えても拒否される操作を、簡単モードでは最初から出さない。右クリックとドロップの範囲を決める |
| 中 | 配布 | ポータブルは既にある。MSI の再現手順を文書化し、未署名でも中身が SwiftPDF 識別子であることを確認する。新しいインストーラー方式は作らない |
| 低 | 画像の挿入と移動 | エンジンはある。既存テキストより画面が大きい。印影の「画像スタンプ」と操作が似て紛らわしい。v0.8 ではやらない |
| 低 | 既存テキストの編集 | 本家の修正が最も厚い領域。解禁すると 10 月後半の編集コミットをまとめて見る必要がある |
| 低 | 注釈、フォーム、墨消し、OCR、権限の変更、署名の作成 | 製品の閲覧専用と逆。本家の未修正（消しゴム）もこの層にある |
| 低 | にじみ、印影の自動縮小 | 印影は v0.7.0 で一区切り。上限超過はエラーのままでよい |

必須テーマの置き場所:

1. ページ操作の充実: 中。v0.9.0。新規実装ではなく許可の追加。
2. 追加テキストの再編集: 実装済み。候補にしない。
3. 画像の挿入と編集: 低。v1.0.0 の候補に留め、v0.8 / v0.9 ではやらない。
4. UI と操作性: 中。拒否される操作を隠すことと、ズーム修正。
5. 保存と印刷: 高。v0.8.0 の本体。
6. 本家からの移植: 高。ただし上の保存・印刷・テキスト・ズームに含まれるものだけ。
7. 配布とインストーラー: 中。手順の固定は v1.0.0。v0.8 ではインストーラーを作らない。

## 11. 推奨ロードマップ

### v0.8.0

テーマは「今出している機能の保存と印刷とテキストを、分岐後の本家修正で安全にする」。

実装する:

- 追加テキストのエンコード修正（CID 0 を避けるコミット）を、差分が印影と無関係だと確認できた場合だけ。
- 別名保存の結果から、古い増分を落とす修正。原本パスへの書き込み拒否は残す。上書き保存は出さない。
- 印刷で非表示レイヤーを出さない修正。印刷は原本を置き換えないまま。
- ズームのスクロール飛び、ダイアログ表示中に保存ショートカットが裏で走らないこと、出力パスが選んだフォルダの外に出ないこと。ポータブルの `Data` を壊さないことを確認してから。
- これらに対する合成 PDF のテスト。既存の印影テストを戻さない。

実装しない:

- ページの追加、削除、並べ替え、回転の保存、抽出、結合、分割。
- 画像の挿入、既存テキストの編集、注釈、フォーム、墨消し、OCR。
- 権限パスワード、電子署名の作成。
- 理事長印の仕様変更（回転、かすれ、承認、履歴、DPAPI）。
- 本家 `main` の一括マージ、Release 0.10 のワークフローのコピー。
- MSI / ZIP の新規ビルドを、この版の完了条件にしない。

### v0.9.0

テーマは「ページの回転、削除、並べ替え、抽出を、別名のコピーにだけ書く」。

実装する:

- 閲覧専用の例外として、その 4 操作だけを許可する。
- 結果は別名保存だけ。原本と、保存先が既にある場合の扱いは v0.8.0 の規則のまま。
- ページが変わったら、理事長印の承認スナップショットは無効のまま。
- Undo は、許可したページ操作と、今あるテキスト、スタンプに限る。

実装しない:

- 結合、分割、ページサイズ、他ファイルからの挿入。
- 本家最新の整理グリッド（Ctrl-ドラッグ複製、逆順）の同時取り込み。分岐点の実装で足りるかを先に見る。
- 画像編集、既存テキスト編集。
- PR #3750 がマージされるまでの範囲入力。空の選択に対する現行の抽出で足りるなら、それを使う。

### v1.0.0

テーマは「配布できる閲覧・テキスト・スタンプ・安全な保存・印刷・限定したページ操作を、手順ごと固定する」。

実装する:

- ポータブルとインストーラーの手順を、このブランチの識別子で再現できるところまで確認する。署名証明書が無い環境では、未署名であると言い、署名できたことにしない。
- 簡単モードに、拒否される詳細機能の入り口を残さない。
- 既知の限界を画面か同梱文書に書く。印影の画素上限、にじみは描かない、既存の本文は編集しない、画像の自由配置は無い。
- v0.8.0 と v0.9.0 のテストを、リリース前に指定クレートだけ再実行する。

実装しない:

- Acrobat 相当の注釈、フォーム、墨消し、OCR、最適化、Office 書き出し。
- 既存テキスト編集と画像編集。必要なら v1.0 のあとで、本家の編集修正を別版として検討する。
- 本家 0.10 系との履歴の統合。
